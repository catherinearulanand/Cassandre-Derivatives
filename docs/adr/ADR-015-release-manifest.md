# ADR-015: One machine-readable release manifest is the source of all claims

## Decision
Version, build ID, test count, dependency versions, supported-product list,
and benchmark results are never hand-typed into documentation. They are
generated by `scripts/generate_release_manifest.py` from the actual build
(git commit hash, lockfile hash, pytest report, migration heads, SBOM digest,
solver build options) into `release-manifest.yaml`.

## S1 implementation and known gap
The generator script exists and produces a real manifest from this session's
actual test run. It does not yet compute image digests (no image build in
this session) or a full SBOM (`pip-audit`/`syft` wiring is backlog). Fields
it cannot yet populate are emitted as `null` with a `"not_yet_implemented"`
reason string — never a fabricated placeholder value.
